          Not in this build

          These are switched off on purpose, and each one says why. None of them produces output in this build, not even an example, because a disabled surface that shows invented data is worse than one that shows nothing.

          • Would carry the same recorded history for an adult with acquired communication difficulty. Off because it has no empirical validation here at all: every number this project has measured comes from infant cries and adult imitations of one.

          • Would apply the same interaction memory in settings where the person cannot report what helped. Off for the same reason, and both sit closer to clinical care than a wellness tool is allowed to.

          • Generates the portable caregiver-to-caregiver document from recorded interactions. This one is built and runs locally on the laptop, not from this page, so nothing here would be fabricated. It is off in the phone client only.

          • Would format the same recorded history for a pediatrician. Off because a document addressed to a clinician invites being read as a clinical finding, which is a line this build does not cross.

          • Would let two caregivers contribute to one record. Off because sharing a recording between people crosses into multi-party consent, which varies by state and is not something a demo can satisfy.

          • Would compare one subject against others. Off because that is human-subjects research and needs an approved protocol, and because this tool deliberately never tells anyone how they compare to normal.

          Audio only, local only. This is a record of what a caregiver said and did. It never reports why a baby is crying, and it shows no confidence numbers - only a status, a band, and plain reasons.
